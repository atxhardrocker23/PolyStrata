# RX 6700 XT official quick/community benchmark suites

Measured 2026-11-10 UTC on one RX 6700 XT 12 GiB (gfx1031), Ryzen 5 3600 (6 cores / 12 host logical threads), 64 GiB physical DDR4-3200, Intel 660p 1 TB NVMe. The Debian 13 LXC had 56 GiB RAM and 10 visible CPU threads; kernel 7.0.14-26-pve. GPU power cap was 211 W and load-time PCIe link was 16 GT/s x16. ROCm SDK wheels were 7.13.0a20260515, AMD clang 23.0.0git, and kernel amdgpu 7.0.14-26-pve. Supplementary package/module identities and their collection timing are in [WHAT_TO_RECORD.md](WHAT_TO_RECORD.md); original harness null fields remain unchanged. Other GPU containers were stopped, no other inference service ran, and a lightweight resource sampler ran outside the guest. No energy-per-token measurement was made.

PolyStrata v0.1.45-poly.9 `83a7a33272413bf87b8d2742dc557c165e2cb2d2`, locally compiled unmodified HIP engine for gfx1031. Engine SHA256 `54c68af73891d7ac77b25af48b83b99bb1ad350f4ed73589a50add58d7e0eaa4`; quick harness SHA256 `aa2672be329f425045d9559f8da165257493c7ca33d6ce4b12053b3fd61d42b1`. The embedded engine version remains0.1.45; release identity comes from the pinned source commit.

The unmodified `tools/strata_bench.py --config <published-config> --long` started a fresh server for each configuration, with its default three repetitions and thinking off. Each suite stored 36 requests: 9 short chats, 9 fresh-prompt requests (3 each near 4K/16K/32K), and 18 agent requests (3 initial turns plus 15 follow-ups). Short chats have a 100-token output cap and fresh prompts a 24-token cap. The changing repository-file agent corpus is tied to the tested source revision. Before measured requests, the upstream harness discards a warm-up chat, two 200/800-word token-ratio calibration probes, and a 1K warm-up prompt. This is the upstream quick/community format, not the draft standard protocol. Engine-reported throughput excludes the other phase; TTFT and total latency are measured by the client. The raw report retains actual prompt/read/reused/output counts, every stored request, medians/ranges, source of timings, and failures/skips. All five PolyStrata and both Strata quick suites had zero failed/skipped stored requests. A successful HTTP request does not establish answer correctness.

All five configurations use65536 context, --kv-whole,8workers,1024MiB reserve, conversation cache0, one request at a time, reasoning off. Qwen UD-Q4_K_M explicitly uses --tail-skip0 as a historical control; other profiles omit the flag and use the tested native default 0. Full startup logs confirm no positive tail-skip setting in any of the five suites. No batch-MTP switch was added. Gemma uses its configured separate Q8 draft; the other models use their configured integrated draft path. Exact flags and file hashes are in each published config/provenance. Each stage had a distinct initially absent expert-profile path, confirmed before starting; the file written adaptively after answers is not an initial seed. The cache0 setting governs conversation checkpoints, while live-session prefix reuse still appears in request counters.

The Q4_K_XL configuration uses the identical main GGUF hash as the same-day Strata quick report. Different engine implementations, drafting/cache policies and repository agent corpora remain; this is a whole-configuration observation, not an isolated kernel speedup or equal-quality claim. Earlier October/November runs used different source corpora, limits/cache settings or hardware and are not controlled baselines. No CUDA/SYCL/Metal build, concurrency suite, quality suite or other quant was tested for this submission.

All files here are official-suite output or supporting configuration/provenance. Private synthetic context/recall comparisons and Avalon experiments are excluded. No engine changes or model weights are submitted. This is contributor evidence, pending maintainer review.
